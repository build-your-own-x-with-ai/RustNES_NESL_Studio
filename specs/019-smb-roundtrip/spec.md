# Feature 019: Super Mario Bros 字节级往返反编译

## 目标

完成**能正常运行**的 Super Mario Bros 反编译，与原始 ROM 对比：

- ✅ 图像完全一致（逐像素帧对比）
- ✅ 运动完全一致（attract 演示 + 实际操作脚本）
- ⚠️ 声音不要求（APU 写入原样保留，不做验证）

## 背景与方法选择

Feature 014/015/018 尝试把 ROM 反编译为高层 NESL 源码，但高层重建不可能保证
帧级一致（信息丢失、时序漂移）。真实世界的"完整反编译"标准（如 smbdis.asm）
是**可重建的注释版汇编源码**：

```
原始 ROM ──反汇编──▶ smb.asm + smb.chr（人类可读、可编辑的源码）
                        │
                        └──重新汇编──▶ rebuilt.nes（与原 ROM 逐字节一致）
```

**逐字节一致 ⇒ 图像与运动必然一致**，再用 nes-sim 做帧级对比测试直接证明。

## 功能需求

### FR-1 完整 6502 反汇编器（字节级精确）

- 覆盖全部 151 条官方指令（含 ASL/LSR/ROL/ROR 累加器模式、JMP 间接模式），
  指令表从 `nesl::asm` 的编码表反向生成，保证编码/解码互逆。
- 从 RESET/NMI/IRQ 向量出发做控制流追踪，区分代码与数据；
  未追踪到的字节以 `.byte` 原样输出。
- 识别 SMB 的 JumpEngine 跳转表惯用法（`JSR JumpEngine` 后跟地址表），
  地址表标记为数据，表项作为新的代码入口继续追踪。
- **不变式：输出覆盖每个 PRG 字节恰好一次**。指令与标签冲突时退化为 `.byte`，
  字节级一致性不受代码/数据误判影响。

### FR-2 可重新汇编的文本格式

- 生成的 `.asm` 为自包含源码：`.ines` 头部指令、`.org`、标签、指令、
  `.byte`/`.word` 数据、`.chr` 引用 CHR 二进制文件。
- 零页与绝对寻址以操作数位数区分（`$XX` = 零页，`$00XX` 四位 = 强制绝对），
  保证重汇编字节一致。
- 文本 6502 汇编器：解析上述格式，两遍汇编，输出完整 iNES 文件。

### FR-3 CLI

- `nesc disasm-full <rom.nes> -o <out.asm> [--chr <out.chr>]`：
  反汇编 + 写出 CHR + 立即自验证（重汇编对比原 ROM，打印结果）。
- `nesc asm <in.asm> [-o <out.nes>]`：从源码重建 ROM。

### FR-4 验证（TDD 测试即验收标准）

| # | 测试 | 验收 |
|---|------|------|
| 1 | 指令表互逆 | 全部官方 opcode 解码→编码 = 原字节；官方指令数 = 151 |
| 2 | ROM 往返 | SMB 反汇编→重汇编，`.nes` 文件逐字节一致 |
| 3 | 标题画面 | 原版与重建版在 nes-sim 中运行，多个检查点帧逐像素一致，且画面非空白 |
| 4 | Attract 演示 | 运行至演示模式，检查点帧一致，且画面随时间变化（证明游戏在动） |
| 5 | 操作脚本 | 按 Start 进入 1-1，按住右+B 并间歇跳跃，检查点帧一致，
    且水平卷轴持续前进（证明 Mario 运动一致且真实发生） |

## 非目标

- 不验证 APU/声音输出。
- 不要求为所有例程命名（向量入口命名为 Reset/NMI/IRQ，其余自动标签 `Lxxxx`）。
- 不改动 014/015/018 的高层反编译管线。

## 使用的原始 ROM

`roms/FC_ROMS-main/ROM/0066/Super Mario Bros. (W) [!].nes`
（iNES：mapper 0 / NROM-256，PRG 32KB × 1，CHR 8KB × 1，垂直镜像，
SHA1 `ea343f4e445a9050d4b4fbac2c77d0693b1d0922`）。
测试在 ROM 文件缺失时跳过（打印提示），避免 CI 失败。
